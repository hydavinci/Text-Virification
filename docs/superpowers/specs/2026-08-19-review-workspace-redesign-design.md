# 审阅工作台现代化重排设计

## 背景

现有审阅工作台经过多轮局部布局调整，已经具备完整的上传、检查、定位、决策、查找替换、批量处理和导出能力，但视觉结构存在以下问题：

- 文件信息、导出、批量处理和查找替换由 `ReviewToolbar` 同时承载，组件职责过重。
- 多层卡片、重复标题和跨组件媒体查询占用空间，信息层级不清晰。
- 窄栏内横向排列字段和按钮会产生换行甚至竖排文字。
- 工具位置随布局变化，用户难以形成稳定的操作路径。
- 当前桌面布局依赖 `display: contents` 和跨组件网格区域，维护成本较高。

本设计在保留现有业务能力和后端接口的前提下，重构审阅工作台的信息架构、组件边界、响应式模式和视觉系统。

## 目标

1. 形成节约、现代、职责清晰的审阅工作台。
2. 让文档成为页面的视觉中心，并获得轨道、已打开侧板和上下文面板之外的全部剩余空间。
3. 让问题、查找、批量和导出具有稳定且易识别的入口。
4. 避免窄栏文字竖排、控件重叠和页面外层滚动。
5. 保持现有审阅、分页、查找、决策和导出行为不变。
6. 建立统一设计变量和响应式规则，移除局部修补产生的交叉样式。

## 非目标

- 不修改后端 API、数据模型或任务生命周期。
- 不改变检查规则、问题分类或决策语义。
- 不增加暗色主题。
- 不引入新的 UI 框架或图标依赖。
- 不重写现有业务 composable。

## 设计方向

采用已确认的 **C2：图标 + 短标签轨道**。

桌面端取消全局顶部栏，使用四区工作台：

1. 左侧 64px 功能轨道。
2. 左侧 280px 可切换功能侧板。
3. 中央自适应文档区域。
4. 右侧 360px 上下文面板。

功能轨道从上到下包含：

- 问题
- 查找
- 批量
- 导出（固定在底部）

每项均显示统一线性图标和短标签，并提供悬浮提示。当前项使用浅靛蓝背景和强调条，不仅依靠颜色表达选中状态。

## 桌面布局

工作台固定为一个动态视口高度，不产生浏览器页面滚动。文档、左侧功能板和右侧上下文面板分别管理内部滚动。

### 功能轨道

- 固定宽度 64px。
- 顶部显示紧凑产品标识，不显示“核验工作台”标题栏。
- “问题、查找、批量”位于上部。
- “导出”固定在底部。
- 点击当前已激活的“问题”或“批量”可收起左侧功能板。
- 收起左侧功能板后，中央文档自动扩展。

### 左侧功能板

宽度 280px，只显示当前轨道功能对应的内容：

- **问题**：问题统计、分类/严重程度/处理状态筛选、关键词搜索、问题列表和加载更多。
- **批量**：当前作用范围、已加载数量、高风险提示、接受当前页和忽略当前页。

“查找”不在左侧显示内容，而是激活右侧上下文面板的“查找替换”页。

“导出”不占用常驻侧板，而是打开锚定在轨道左下角的弹出面板。

### 中央文档区

- 始终是页面最大区域。
- 顶部使用约 48px 的粘性文档标题条，显示文件名、文件格式、已加载段落数和问题数。
- 文档正文独立滚动。
- 保留正文高亮、重叠问题循环选择、焦点恢复和分页 sentinel。
- 不显示重复的全局文件标题或“文档审阅”眉题。

### 右侧上下文面板

固定宽度 360px，使用两个页签：

- **问题详情**
- **查找替换**

问题详情显示当前问题的严重程度、原文、建议、上下文和决策操作。

查找替换采用纵向字段布局：

1. 查找内容
2. 替换为
3. 匹配状态
4. 上一处、下一处、全部替换操作行

任何按钮文字不得折成竖排。页签内容独立滚动，页签头固定。

## 交互状态

`ReviewWorkspaceView` 新增纯展示状态：

- `activeRailTool`: `issues | search | batch`
- `activeSidePanelTool`: `issues | batch`
- `isSidePanelOpen`: boolean
- `activeInspectorTab`: `details | search`
- `isExportOpen`: boolean

业务状态继续由 `useReviewWorkspace` 管理。

### 状态转换

- 点击“问题”：激活问题轨道项，打开/激活问题侧板，并激活右侧问题详情页。
- 再次点击已激活的“问题”：收起左侧板。
- 点击“批量”：激活批量轨道项，并打开/激活批量侧板。
- 再次点击已激活的“批量”：收起左侧板。
- 点击“查找”：激活查找轨道项和右侧查找替换页，不改变 `activeSidePanelTool` 或左侧板开关状态。
- 点击“导出”：切换导出弹层。
- 点击问题列表项或正文高亮：选择问题并激活问题详情页。
- 在查找页点击上一处/下一处：保持查找页激活，不因内部匹配选择切换到问题详情。
- 关闭导出弹层：保留导出任务、警告、失败或下载状态。

## 组件边界

### 新增组件

#### `ToolRail`

负责轨道展示和交互，不读取业务 API。

输入：

- 当前工具
- 左侧板开关状态
- 导出弹层状态

输出：

- 激活问题
- 激活查找
- 激活批量
- 切换导出

#### `WorkspaceSidePanel`

作为问题板与批量板的稳定容器，负责标题、关闭按钮和内部滚动。

#### `ContextInspector`

负责右侧页签、页签焦点管理和内容区域，不直接处理问题或查找业务。

#### `DocumentHeader`

显示文件名、格式、段落数和问题数。该组件位于 `DocumentViewer` 内部或作为其明确子区域，不创建全局顶栏。

### 调整现有组件

- `ReviewToolbar` 被移除。其文件信息迁移到 `DocumentHeader`，子功能迁移到对应区域。
- `ReviewNavigation` 保留问题统计、筛选和列表，移除对外层卡片样式的假设。
- `BatchActions` 成为左侧板内容，保留作用范围与高风险确认。
- `FindReplace` 成为右侧页签内容，移除为横向工具栏设计的媒体查询。
- `ExportPanel` 成为带标题和关闭行为的弹出内容，保留完整导出生命周期。
- `IssuePanel` 成为右侧页签内容，移除外层卡片职责。
- `DocumentViewer` 接收文件元信息用于 `DocumentHeader`，保留正文行为。

## 视觉系统

### 颜色

- 页面背景：中性浅灰。
- 面板背景：白色。
- 主强调色：单一靛蓝。
- 文本：深灰、次级灰两级。
- 严重程度颜色仅用于徽标、图标和高亮，不用于整块大面积背景。

### 尺寸与间距

- 基础间距：4px。
- 常用间距：8px、12px、16px。
- 面板圆角：10–12px。
- 控件最小高度：44px。
- 正文字号：14px。
- 辅助字号：12px。
- 面板标题：16px。

### 层级

- 主面板只使用一层边框和极轻阴影。
- 内部分组使用留白、分隔线和标题，不使用嵌套卡片。
- 仅主要动作使用实心按钮。
- 次要动作使用浅底或描边按钮。
- 禁用文字保持可读对比度。

### 图标

使用项目内统一的轻量 SVG 图标组件或内联 SVG，不新增第三方图标包。所有纯图标按钮必须有可访问名称；轨道按钮同时显示文字标签。

## 导出弹层

- 从左侧轨道底部向右上方展开。
- 桌面宽度约 360px，最大高度受视口限制，内容可滚动。
- 使用 `role="dialog"`、可访问标题和关闭按钮。
- 打开时焦点进入弹层首个可操作控件。
- Escape 关闭。
- 关闭后焦点返回导出按钮。
- 点击弹层外关闭，但进行中的导出请求不会取消。

## 响应式设计

### 1280px 及以上

使用完整桌面布局：轨道、可选左侧板、文档、右侧上下文面板。

### 768–1279px

使用单文档主视图和底部功能导航：

- 文档
- 问题
- 查找
- 批量
- 导出

每次只显示一个主要面板。导出仍使用弹层。

### 767px 及以下

沿用相同底部导航，但减少左右边距。问题详情作为问题视图内的子页；返回操作恢复到问题列表和原焦点。

## 错误与状态反馈

- 总览加载失败：显示在文档标题条内，提供重试。
- 问题加载失败：显示在问题侧板。
- 决策失败：显示在问题详情。
- 批量失败：显示在批量侧板。
- 查找/替换失败：显示在查找替换页。
- 导出警告、失败和下载：显示在导出弹层。
- 检查器部分失败：在问题侧板顶部显示紧凑警告，不创建全局横幅。
- 保留 `aria-live` 决策播报。

错误不得通过成功样式或静默默认值隐藏。

## 可访问性

- 使用 `nav` 表示功能轨道。
- 轨道按钮使用 `aria-current` 或 `aria-pressed` 表示状态。
- 左侧板和右侧面板具有明确可访问名称。
- 右侧页签实现标准 tab/tabpanel 键盘模型。
- 导出弹层实现焦点进入、焦点锁定、Escape 关闭和焦点返回。
- 所有控件维持至少 44×44px 触控区域。
- 保留可见焦点环和减少动态效果支持。
- 颜色不作为唯一状态信息。
- DOM 顺序与主要键盘流程一致：轨道、左侧板、文档、右侧面板。

## 测试策略

### 组件测试

- `ToolRail` 激活、收起、导出开关和键盘操作。
- `ContextInspector` 页签切换、焦点移动和状态保持。
- `ExportPanel` 弹层焦点与生命周期。
- `DocumentHeader` 文件元信息和错误状态。

### 工作台集成测试

- 问题列表和正文高亮选择切换到问题详情。
- 查找上一处/下一处保持查找页。
- 左侧板收起后文档区域扩展。
- 批量和导出行为继续调用现有业务方法。
- 窄屏底部导航保留状态和焦点。

### 布局几何测试

在浏览器测试中覆盖：

- 1366×768
- 1440×900
- 1920×1080
- 1279px/1280px 临界点
- 768×1024
- 390×844

验证：

- 页面无非预期外层滚动。
- 轨道、侧板、文档和上下文面板不重叠。
- 文档为最大内容区域。
- 查找字段和按钮不裁切、不竖排。
- 弹层不超出视口。

### 回归测试

保留并适配现有测试：

- 问题分页和筛选。
- 高亮选择与重叠循环。
- 决策冲突与重试。
- 查找替换。
- 批量决策。
- 导出生命周期。
- 响应式和可访问性。

## 实施顺序

1. 建立统一设计变量和工作台外壳。
2. 新增 `ToolRail` 和布局状态。
3. 将问题与批量迁移到 `WorkspaceSidePanel`。
4. 新增 `ContextInspector`，迁移问题详情与查找替换。
5. 新增 `DocumentHeader` 并移除全局顶部栏。
6. 将导出迁移到轨道弹层。
7. 实现平板/移动底部导航。
8. 删除旧 `ReviewToolbar` 和交叉媒体查询。
9. 运行行为、布局几何、构建和无障碍验证。

每一步使用 TDD，保持主分支可运行，不在同一步混入无关业务改动。

## 验收标准

- 桌面无全局顶部栏。
- 轨道使用图标加短标签，导出位于左下角。
- 问题、查找、批量、导出职责和入口清晰。
- 文档在桌面布局中占据最大区域。
- 右侧查找替换无竖排或控件重叠。
- 页面在目标桌面尺寸无外层滚动。
- 窄屏操作可达且内容不裁切。
- 所有现有业务流程和错误处理继续工作。
- 自动化测试、类型检查和生产构建通过。
